\section{Technical Architecture and Choices}\label{sec:architecture}

\subsection{Algorithm: Knowledge-Guided Deep Reinforcement Learning}

The dynamic reconfiguration scheduling problem for Personalized Customization Tasks (CPP) is formulated as a Markov Decision Process (MDP). 

\textbf{State space} encodes features for all machine and task nodes, including working state, idle time, reachable nodes, time utilization, stage count, and processing speed.

\textbf{Action space} comprises joint decisions of stage selection and machine allocation, including a \textit{None} action to reserve capacity for future efficiency.

\textbf{Reward function} drives optimal scheduling by calculating the negative expected completion time and penalizing machine reconfiguration delays.

The core algorithmic contribution is the \textbf{KGDRL architecture}, which integrates three mechanisms:

\begin{enumerate}
    \item \textbf{State Encoding}: Represents the workshop as a graph, merging task and machine vectors into a unified action vector.
    \item \textbf{Knowledge Guidance Network}: Employs an L1 norm activation and IF-THEN heuristics (prioritizing shorter reconfiguration times and heavier workloads) to balance exploration and exploitation.
    \item \textbf{PPO Optimization}: Utilizes an Actor-Critic deep network structure with clipped objectives to ensure stable and convergent policy updates.
\end{enumerate}

\subsection{Adoption-Centric Design: Why a Warehouse Manager Would Trust It}

The main barrier to AI adoption in warehouse operations is rarely algorithmic accuracy; it is organizational risk. Maverick-SORT was therefore designed not only to optimize scheduling decisions, but also to reduce the perceived cost of trying a new system.

\begin{itemize}
\item \textbf{Trust through explainability}: In a GSP-regulated environment, black-box recommendations are difficult to justify. By anchoring KGDRL to established operational heuristics, the system produces recommendations that remain interpretable and consistent with managers' existing decision logic.

\item \textbf{Trialability through risk reversal}: Most warehouse managers lack the time, budget, and organizational support required for a lengthy software pilot. The browser-based Essential Edition enables five-minute ``What-If'' simulations without touching live systems, lowering the activation energy of adoption.

\item \textbf{Value through visible outcomes}: Rather than promising generic efficiency improvements, the system makes operational trade-offs explicit and quantifies potential savings. Managers can evaluate the impact of different scheduling strategies before committing to implementation.
```

\end{itemize}

The design principle is simple: adoption depends less on whether the algorithm is marginally better, and more on whether decision-makers can understand it, try it safely, and see clear value from using it.

The Streamlit choice is worth explaining. We needed a runnable prototype that Wang Li could access via a web browser without installation. Streamlit's ``rerun-on-change'' model is imperfect for real-time dashboards (see Section~\ref{sec:results}), but it reduces deployment friction to near zero---critical for a product whose first hurdle is simply getting the user to try it.
